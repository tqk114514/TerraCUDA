# MC 26.3 噪声栈移植评估：TerraCUDA 的下一个版本？

> 2026-10-13。§17 判决后 offload 形态的无头管线已贴近结构上限，分岔指向 26.3 适配重估。
> 本评估把 26.3 的噪声栈（loom 本地缓存的 merged-deobf jar，vineflower 反编译精读）与
> 26.1.2 逐点对照，给出移植面、工作量与价值账本。**结论先行：技术上是一次"换弹"而非
> "重造"——密度栈 float 化反而让 GPU 路径更简单更便宜；但 vanilla 基线缩小一个量级、
> 且 zFastNoise 已占住 CPU 侧的 1.46×，边际收益是 26.1 时代的三分之一。**

## 1. 26.3 噪声栈的五个结构性事实（源码实读）

1. **全 float**：`DensitySampler.sampleValue(...) → float`，整条密度链 binary32。
   26.1 时代的双精度铁律（`--fmad=false` 之下的 double 语义复刻）大部分**作废**——
   parity 目标直接变成 IEEE 754 binary32，GPU 与 Java 同型，比 double 复刻便宜得多。
2. **体积采样是一等公民**：接口自带 `sampleVolume(SamplerContext, DensityBuffer,
   DensityVolume)` + naive 逐点回退；vanilla 自带 `DensityBufferPool/Arena/Scoped`。
   **官方钦定了批量入口**——26.1 时代预判的"比 fillFromNoise 干净一个量级的注入点"
   落地了：GPU 实现只需替换顶层 sampler 的 `sampleVolume` 一个方法。
3. **密度求值搬家**：`NoiseChunk` 从 26.1 的求值引擎缩成 69 行的壳（组装上下文、
   拿 buffer 池、建缓存采样器、建 aquifer）；求值本体在 `densityfunction` 包
   （DensitySamplerSet/CachingDensitySampler/SamplerContext/DensityFunctionCompiler）。
   Beardifier/Blender 变成 **SamplerContext 的 user fields**——我们的 beardifier 收编
   方案在新栈里有了官方挂点。
4. **管线同构、一处理名**：金字塔仍是同构 12 步（NOISE → **TERRAIN**；`buildSurface`
   并入 TERRAIN 的异步体内，SURFACE 疑似不再是独立状态）；`ChunkStep.apply` →
   `ChunkStatusTask.doWork`、TERRAIN 体仍 `supplyAsync("buildTerrain")` 逃逸到池。
   **我们的调度层资产（L1/L3/L2 mixin、LayerTiming、基准协议）打点名字在 26.3 原样存在，
   近乎逐字平移。**
5. **噪声原语改名族**：synth 下是 `Noise`/`GradientNoise` 等（ImprovedNoise 时代结束），
   密度算子族在 `DensityFunctions`——lowering 的目标 DAG 换了一版。

## 2. 移植面账本

| 资产 | 26.3 命运 | 工作量 |
|---|---|---|
| CUDA/FFM 基础设施（CudaContext/多流/pin/NVRTC） | **原样** | 0 |
| 调度层（ChunkStepMixin/ChunkTaskDispatcher/ThreadingDetector/LayerTiming/offload 包） | **打点同名的近逐字平移** | 小（验证级） |
| 基准协议 + thread-sampler + 性能笔记方法论 | 原样 | 0 |
| parity 原语（noise/random/math 参考实现 + 全部逐位测试） | **float 化重推导重验证**——更快更简单，但每个原语重测 | 中（测试架构原样、目标全换） |
| 密度 lowering（DensityProgram/Image/Interpreter） | 架构**保留**、目标 DAG **重定向**（新算子族 + sampleVolume 批量形态） | 中偏大 |
| aquifer/规则 replay | API 变形（`aquifer.create(samplers, randomFactory, volume, picker)`），概念同构 | 中 |
| NOISE 接管注入点 | fillFromNoise mixin → **顶层 `DensitySampler.sampleVolume` 替换**（更干净） | 小 |
| 多版本基建（NeoForge 26.3、mixin 双版本、测试夹具双版本） | 新增 | 中 |

量级判断：**几周量级的中型项目**，主要成本在 parity 测试目标的 float 化重验证与
lowering 重定向；没有 26.1 时代那种"从零推双精度语义"的深水区。

## 3. 价值账本（同机实测背书）

| | vanilla | mod | 倍率 |
|---|---|---|---|
| 26.1.2 阶段体（单线程） | ~40 ms（历史记录） | ~7 ms（GPU 2.85 + replay） | ~5-6× |
| 26.3 阶段体（zFastNoise JMH，种子 123） | **11.53 ms** | zFastNoise CPU 侧 7.88 ms | 1.46× |
| 26.3 GPU 路径（推算） | 11.53 ms | **~2-4 ms**（float 内核 + CPU 填充半场） | **~3-5×** |

- float 化对 GPU 是**双重利好**：parity 更简单（同型 binary32）+ 内核更便宜（26.1 的
  kernel 在消费卡上背 double 语义的包袱；RTX 3080 的 FP64 吞吐是 FP32 的 1/64）。
- 但绝对优势缩水：vanilla 基线小了一个量级，zFastNoise（MPL-2.0、已发布、占据
  populate 半场）把 CPU 侧天花板抬到 7.88 ms——GPU 密度路径的**净空间 ≈ 11.53−2-4 ms
  ≈ 7-9 ms/区块**，是 26.1 时代（~33 ms）的**四分之一到三分之一**。
- 调度层资产跨版本保值是确定的（§1.4）；端到端的 2.15× 判决在 26.3 大概率重演
  （dispatcher 墙不随噪声栈换代消失）。

## 4. 建议

1. **值得做，但按"26.1 是基本盘"的优先级排**：26.3 移植的本质是把 mod 的 edge 从
   "~33 ms/区块的真空"搬进"~8 ms 净空间的竞争"。立项的第一周应该是 parity 原语的
   float 化（收益立现、风险最低、测试架构全复用），而不是管线。
2. **先平移调度层做 26.3 vanilla 的归因**（ChunkStepMixin 的打点同名，几乎免工）：
   用 LayerTiming 测 26.3 的管线 dwell——如果 dispatcher 墙仍钉着端到端，26.3 的
   首发卖点应该和 26.1 一样是 offload 包，而不是 GPU。
3. **zFastNoise 的存在不是威胁是互补**：它占 populate 半场（MPL，只参考不抄），我们占
   密度半场——"GPU 密度 + 它的填充优化"在 26.3 理论可叠加（各自管线内正交）。
4. 铁律更新：`--fmad=false` 与"逐字移植"**仍然全部适用**（float 也有舍入与结合序）；
   "double 语义复刻"类教训（ldexp、f64 陷阱）归档为 26.1 专属史。
