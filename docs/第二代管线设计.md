# TerraCUDA 第二代管线设计：GPU 主导的区块生成（26.1.2）

> 2026-10-13。方向裁决（用户）：**不移植 26.3**，26.1.2 是未完成的战场——目标是 C2ME 式的
> 整管线重构，把**合适的逻辑搬入 GPU**，让 GPU 与 CPU 高效协作。本设计把该愿景翻译成
> 可实施的分代计划，全部锚定在 §13–§18 的测量、26.1.2 反编译事实与既有资产上。

## 1. 愿景翻译：两半重构，一半已完成，一半是本 mod 的差异化

"像 C2ME 那样重构管线"拆成两半看：

- **CPU 侧调度重构——已经建成并测完**。§15–§17 的 offload 包就是我们的 FlowSched-lite：
  阶段体下放、FEATURES 仲裁、lane 实验、逐层归因。它的天花板也量过了：offload 态的
  层间 requeue 只剩 2–13 ms、FULL 塌缩到 4.5 ms、L2 负优化——**再往调度层砸工程，
  追的是个位毫秒，这不是主战场**。历史背书：旧实验线用比 C2ME 轻得多的机制跑赢过它
  的无头成绩（2:07 vs 2:19）。
- **GPU 侧扩展——真正的差异化重构，也是现状的真瓶颈所在**。今天 GPU 只做密度+矿脉
  （服务 2.85 ms/区块，busy 72–81%），逐块决策的另一半（material rules + aquifer，
  4.8 ms）仍在 CPU replay worker 上，靠一条 16 深队列和两个 worker 与设备线程接力。
  §17 量出：**noise 阶段 svc 105–146 ms 中，GPU 数学只占 2.85 ms**——其余全是波纹
  爆发下的队列与接力。第二代管线要消灭的正是这个结构。

## 2. 第二代结构：GPU 从"NOISE 体执行器"升级为"波纹感知的批量决策阶段"

三阶段递进，每阶段独立开关、独立验收、无 parity 风险前置。

### G1：波纹批处理（cohort batching）——先做的吞吐与延迟杠杆

**机制**：波纹把一圈 ~12 个相邻区块几乎同时推进到 NOISE（§17 的 12 深队列就是它的
签名）。第一代设备线程一次吃一个区块、每区块 3 次内核启动（density/veins/回传）。
G1 在 `GpuWorldgenService` 的设备队列上加聚合：**同波到达的区块合并为一次批次**
（一次排空等待中的兄弟作业，N 个区块共享一组启动），内核索引按区块数参数化，批次
完成后再按区块扇出各自的 future。

**收益预测（锚定测量）**：
- 每次 0.2–0.5 ms 的启动固定成本摊薄 12×；
- **队列爆发被批次吸收**：12 深的串行等待变成一次并行批——noise svc 的 105 ms p50
  中约 96 ms 是 16 深队列等待（§17 的 96≈16/166 自洽），批处理让波纹以"整波"为单位
  通过，预期 svc p50 掉到 30–50 ms 一带；
- 无 parity 风险：数学一字不变，只是批几何。
**量级**：天级。**验收**：91 测试 + 同日背靠背 + LayerTiming 的 noise svc/queue 对照。

### G2：规则与 aquifer 上 GPU——"搬入 GPU"的核心

**机制**：`MaterialRules` 树（661 行解释器、61 个算子点）走 `DensityCompiler` 的既有
路线——**lowering 成程序镜像、编译进 CUDA**，与密度/矿脉同一设备管线；replay worker
退化为纯写回（2.1 ms）。GPU 输出从"密度数组"变成"逐块状态判定"，CPU 只剩把状态写进
区块。

**为什么 M3 时代的否决不再成立**（`913865f` 记录的三条理由逐条重审）：
1. "每线程一份网格与缓存"——flat cache 的键是**区块上下文**，不是线程：GPU 上它是
   每批次一次的内核参数/常量内存，比 CPU 每线程复制更便宜；
2. "分支与表驱动、浮点占比低"——分支发散在批内区块间并行下伤害有限，且表是只读的；
3. "收益很小"——M3 时代 rules 是串行管线里的 5 ms；今天它是 2.15× 管线的 CPU 半场、
   noise 阶段延迟（105–146 ms）的构成者。**算盘换了，判决可以合法重审。**

**收益预测**：阶段内接力消失（设备→replay 队列→worker 的两跳），noise 阶段单线程容量
从 ~350/s 抬到 ~220+/s（服务 2.85+规则 GPU 化 ≈ 4–4.5 ms），CPU 侧两个 worker 空出来。
**量级**：周级（parity 面大：每个规则算子、aquifer 网格、流体判定都要逐位测试——但
测试架构现成，铁律流程走过一遍）。**风险**：aquifer 是深水区，独立子阶段单独验收。

### G3：天花板破除——后 G2 世界的两道墙

§17 已量出 G1+G2 之后的墙位，G3 是对着它们打：
1. **FEATURES 线程容量 ~222/s**（4.5 ms/区块单线程）：并行已判死（parity），剩下的是
   **契约安全的执行优化**——不改输出只提速。栈采样的靶点现成：块读取热路径
   （ProtoChunk.getBlockState 22% + PalettedContainer 9% + BulkSectionAccess 5%），
   每区块一份 section 视图缓存即可吃下大半。
2. **光车道**（wall 16 ms/批）：批参数与共享性待归因（LayerTiming 已可测）。
3. 主线程 FULL/tick 节拍在客户端场景的残余（§16 已证无头下塌缩）。

## 3. 数字沙盘（诚实的天花板算术，cap 50 声明）

| 阶段 | noise svc p50 | dwell p50 预期 | 新约束位 |
|---|---|---|---|
| 现状（L1+L3） | 105–146 ms | 175–217 ms | 波纹队列 |
| +G1 批处理 | **~30–50 ms** | ~130–160 ms | features 队列显形 |
| +G2 规则上 GPU | ~15–30 ms | ~100–130 ms | **features 线程 ~222/s、光 lane** |
| +G3 天花板破除 | — | 视 features 优化幅度 | 光 lane / Chunky cap 本身 |

- cap 50 下 dwell 130 ms → ~380 cps 理论，但 features 线程 222/s 先到——**G3 不是可选项
  而是 G2 之后的必经**。全部落位后的无头预期在 **222–280 cps（~1:20–1:43）** 一带。
- **客户端场景是更大的赢家**：吞吐 = 4÷dwell，dwell 每砍 100 ms 都是直接倍增级——
  G1+G2 把客户端 dwell 从 ~600+ 砍到 ~150-200 ms 的量级（未测，标为推断）。
- 以上全部标注：单场端到端 ±18%，验收只认同日背靠背 + 分段归因。

## 4. 不变式（全部沿用，一代管线的纪律带进二代）

1. 逐位 parity：每个 GPU 化的规则算子对 vanilla 有逐位测试；CPU 参考实现同样验证。
2. 铁律全套（`--fmad=false`、逐字移植、float 语义、ldexp）适用于 G2 的每一个内核。
3. 一阶段一验收：91 测试全绿 + 同日背靠背 + LayerTiming 归因对照，负结果照录入档。
4. G1/G2 各自默认关（`-Pbatch`、`-PrulesGpu` 之类），出问题回退到上一代形态。
5. C2ME 只做设计参照（MIT 部分），一行不抄；它的教训（fixes-* 税单）继续为我们标雷。

## 5. 路线图（G1 实测后修订，2026-10-13）

1. **G1 已落地并实测——判决为负（性能笔记 §19）**：波机制成立（平均 14.2 区块/波、
   parity 逐位背书），但"批处理-屏障"把逐区块流水线的跨区块重叠拆成两段串行——
   noise 阶段延迟翻倍、dwell 持平、端到端持平。与 L2 同构：**cap 下重排延迟分布不产生
   吞吐**。`-Pbatch` 默认关保留；"流水线化波"（按每区块流事件逐个移交、保留启动摊薄
   又拆掉屏障）是记录在案的推断级假设，非立项承诺。
2. **G2 因此成为唯一剩下的结构杠杆**，提前为主：分两步——先 rules 树 lower + 镜像
   （不含 aquifer，veinifier 已在设备侧），验收；再 aquifer 网格上设备，独立验收。
   它消灭的是设备+relay 的接力本身（砍停留总量），不是重排它。
3. **G3 按 §17 栈采样靶点**逐个做，每个有前后归因。
4. 全程 LayerTiming 开着跑——上一代仪表就是二代管线的验收秤；G1 的三次"延迟重排死路"
   判决（L2、G1、replayCapacity 的对照）都靠它当场定案。
